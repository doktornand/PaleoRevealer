🏛️ 1. Architecture Framework · Niveau ADN fossile

Pipeline en 5 phases — Comme extraire l’ADN d’un moustique dans de l’ambre :

[1] CHARGEMENT   → Parser MZ / COM / ASM brut
[2] ANALYSE      → CFG, Dataflow, patterns SCADA/IoT
[3] TRANSFORMATION → Moteur de règles hiérarchiques (11 catégories)
[4] EMISSION     → Backends MASM, NASM, PE (Win32)
[5] VALIDATION   → Revues manuelles, rapports JSON
📦 loader/ MZ, COM, PE generator
⚙️ core/ Pipeline, rule engine, analyse
🔌 plugins/ BCD, far calls, Bridge IoT, DOS/BIOS dispatch
🎛️ backends/ MASM, NASM, PE emission

🗃️ Configs dynamiques : hierarchical_rules.json · iot_mappings.json · pe_templates.json

⚠️ 3. Limites (fossiles fragiles)

  • ❌ Pas de support pour les DOS extenders (DPMI, DOS4GW, mode protégé 16/32)
  • ❌ .COM > 64KB non supporté (limite structurelle)
  • ❌ Pas de rétro-conversion Win32 → DOS
  • ❌ Pas de GUI pour configurer les règles JSON (éditeur manuel requis)
  • ❌ La génération PE peut nécessiter revues manuelles (zones marquées dans rapport)
  • ❌ Mapping IoT limité aux périphériques définis dans iot_mappings.json
  • ⚠️ Les TSR DOS ne se comportent pas comme des processus Win32 classiques (nécessite adaptation)
  • 🦕 Code fortement obfusqué ou auto-modifiable → résurrection difficile

Recommandation InGen : commencez toujours par --report pour évaluer le taux de complétude avant conversion massive.

🗺️ 6. Workflow recommandé – Plan d'extraction Hammond

1. [ANALYSE INITIALE]
   node cli.js --report legacy.exe
   → Examiner le JSON, identifier les interruptions non gérées

2. [CONFIGURATION SUR MESURE]
   nano config/iot_mappings.json   # mapper vos adresses I/O spécifiques
   nano config/hierarchical_rules.json   # augmenter priorité certaines règles

3. [CONVERSION ITERATIVE]
   node cli.js --mz-to-pe --debug legacy.exe -o test_cycle1.exe
   → Tester, ajuster les templates PE

4. [REVUE MANUELLE]
   Ouvrir les zones marquées "manual_review_needed" dans le rapport

5. [PRODUCTION FINALE]
   node cli.js --no-comments --subsystem WINDOWS final_ingen.exe

🧪 Détails des plugins spécialisés (extinct instruction revival)

  • BCD Emulator : restaure AAA, DAA, AAS, DAS (instructions arithmétique décimal, souvent mortes)
  • Far Call Resolver : transforme CALLF/JMPF 16:16 en callbacks Win32 ou thunks
  • IoT Bridge : capture OUT/IN et redirige vers API Windows (ex: pour piloter des equipements legacy)
  • DOS/BIOS Interrupt Dispatcher : convertit INT 21h, INT 10h, INT 13h en appels équivalents Win32

Ces plugins sont activables automatiquement selon le contexte et les règles.

🧬 Jurassic Park Avertissement : Bien que PaleoRevealer ramène à la vie des dinosaures binaires, certaines créatures restent instables. Testez toujours sur machine virtuelle avant déploiement en production. Les programmes qui manipulent directement l'IVT (Interrupt Vector Table) ou qui utilisodes appels INT 0x2F (multiplex) nécessitent des revues spécialisées.

⚙️ Options CLI avancées (paddock control)

--scada               → Active les mappings IoT (ports série, parallèle, timers)
--report              → Génère un fichier .report.json (analyse post-mortem)
--no-comments         → Supprime les commentaires du code généré
--debug               → Logs détaillés du pipeline
--format masm|nasm|pe → Choix du backend
--subsystem CONSOLE|WINDOWS
--com-to-pe, --mz-to-pe  → Conversion directe d'exécutables

🧩 Extension guide : création d'un plugin "Ankylosaurus Armor"

Pour ajouter votre propre module de transformation :

// src/plugins/ankylosaurus_armor.js
class AnkylosaurusPlugin {
    constructor() { this.name = "AnkylosArmor"; }
    process(instruction, context) {
        if(instruction.mnemonic === "INT" && instruction.operands[0] === "0x13") {
            // redirige INT 0x13 (disque) vers la logique moderne
            return { ...instruction, comment: "; resurrected disk access" };
        }
        return instruction;
    }
}
module.exports = AnkylosaurusPlugin;

// Puis dans src/core/pipeline.js, importez et ajoutez à la chaîne.
